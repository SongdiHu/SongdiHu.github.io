Sorting Algorithms - Concise Overview

The main purpose of this article is to review the basics of sorting algorithms.

1) What Is Sorting?

Sorting reorders items (numbers, strings, records) into a specified order. Your choice of algorithm affects speed, memory, stability, and robustness.

2) Taxonomy

  • Comparison-based (general purpose): Insertion, Selection, Bubble, Merge, Quick, Heap, Shell, Introsort (C++ std::sort), Timsort (Python sort/sorted).
    • Theoretical lower bound: any comparison sort needs Ω(n log n) comparisons in the worst case.
  • Non-comparison (key‑aware): Counting, Radix (LSD/MSD), Bucket.
    • Achieve near‑linear time when assumptions hold (e.g., small integer ranges, fixed‑width keys, or uniform distributions).

3) Core Properties

  • Time Complexity: best / average / worst growth (Big‑O).
  • Space Complexity: extra memory beyond input (in‑place O(1) vs. O(n) auxiliary).
  • Stability: equal keys keep original order (important for multi‑key pipelines).
  • Adaptivity: improves on nearly‑sorted inputs (e.g., Insertion, Timsort).
  • In‑place: uses constant extra memory (Heap sort; many Quicksorts use O(log n) stack).
  • Deterministic Worst‑Case: some guarantee O(n log n) worst‑case (Merge, Heap, Introsort).

4) Comparison‑Based

Insertion Sort

  • Idea: Insert each element into the correct position within a growing sorted prefix.
  • Traits: Stable, in‑place, adaptive; excellent on small/nearly‑sorted data.
  • Cost: Best O(n), average/worst O(n²).

Selection Sort

  • Idea: Repeatedly select the minimum and place it in front.
  • Traits: In‑place, not stable; simple but slow.
  • Cost: Always O(n²).

Bubble Sort

  • Idea: Swap adjacent out‑of‑order pairs; large elements “bubble” to the end.
  • Traits: Stable, in‑place; mainly pedagogical.
  • Cost: Best O(n), average/worst O(n²).

Merge Sort

  • Idea: Divide and conquer; sort halves and merge.
  • Traits: Stable; predictable O(n log n); uses O(n) extra memory; parallel‑friendly.
  • Cost: O(n log n) in all cases.

Quick Sort

  • Idea: Partition around a pivot; recurse on partitions.
  • Traits: Typically in‑place (O(log n) stack), not stable; very fast on average; worst‑case O(n²) mitigated by good pivoting/hybrids.
  • Cost: Average O(n log n); worst O(n²).

Heap Sort

  • Idea: Build a heap; repeatedly extract the extremum.
  • Traits: In‑place O(1) extra, not stable; steady O(n log n) with weaker cache locality.
  • Cost: O(n log n) in all cases.

Shell Sort

  • Idea: Generalized insertion with decreasing gaps.
  • Traits: In‑place, usually not stable; performance depends on gap sequence; practical for medium sizes.
  • Cost: Varies with gaps (e.g., between about O(n^{4/3}) and O(n log² n)).

Introsort (C++ std::sort)

  • Idea: Start with quicksort; if recursion becomes too deep, fall back to heapsort; insertion for tiny parts.
  • Traits: In‑place, not stable; robust O(n log n) worst‑case, excellent practical speed.

Timsort (Python list.sort/sorted)

  • Idea: Detect naturally sorted runs and merge adaptively.
  • Traits: Stable, adaptive; near‑linear on nearly sorted inputs; O(n log n) worst‑case.

5) Non‑Comparison

Counting Sort

  • Assumptions: Integer keys in a small, known range.
  • Traits: Stable (with appropriate output step); memory O(n + k).
  • Cost: O(n + k), where k is range size.

Radix Sort (LSD/MSD)

  • Assumptions: Keys decomposable into digits/bytes (e.g., fixed‑width integers, certain strings).
  • Traits: Typically stable per digit pass; often uses counting sort internally.
  • Cost: O(d·(n + b)), d = digits, b = bucket/base size.

Bucket Sort

  • Assumptions: Keys approximately uniform over an interval.
  • Traits: Distribute into buckets, sort each (often with insertion), then concatenate.
  • Cost: Average O(n) under distribution assumptions; worst O(n²) if heavily skewed.

Non‑comparison sorts excel when assumptions hold; otherwise choose comparison sorts.

6) Decision Guide

  • Default general‑purpose: Introsort (std::sort) - fast and robust.
  • Need stability / multi‑key pipelines: Merge‑based or Timsort (std::stable_sort in C++ is merge‑like).
  • Nearly sorted / tiny arrays: Insertion (or Timsort).
  • Memory‑tight (in‑place): Heap sort or guarded Quicksort.
  • Integer keys, bounded range or fixed width: Counting or Radix.
  • Huge / external data: Multi‑way external merge; parallel merge/sample‑based sorts.

7) Practical Considerations

  • Data: size, partial order, duplicates, distribution, key type (ints/strings/structs).
  • Constraints: stability, memory, worst‑case guarantees, latency vs. throughput.
  • Systems: cache locality, branch prediction, vectorization, parallelism; I/O for external sorting.
  • Library first: Prefer high‑quality standard/library sorts unless you have a specific reason not to.
