AWS EC2 Deployment Guide: From HTTP Timeouts to Broken Icons (CORS Fixes)

After migrating a website to AWS EC2 and configuring an SSL certificate, you might encounter two incredibly deceptive “ghost issues”:

  1. Accessing the site via the domain initially hangs for seconds or throws a timeout before eventually loading.
  2. Once the site opens, icons (like FontAwesome) and certain button styles are broken, accompanied by a sea of red errors in the console.

Today, we will break down the underlying logic of these two classic deployment traps.

Issue 1: The “Double Firewall” Timeout Trap

When you finish your SSL setup and type yourdomain.com into your browser, it spins for several seconds and shows ERR_TIMED_OUT. A moment later, the browser’s built-in “HTTPS-First” fallback mechanism tries port 443, and the site finally opens.

The Underlying Logic:
Browsers default to Port 80 (HTTP) first. If that request is silently dropped (not rejected, but ignored), the browser waits for the timeout before trying the next protocol.

The Reality:
Your server actually has two layers of protection:

  • The Outer Gate: AWS Security Groups. You likely opened port 80 here.
  • The Inner Door: Ubuntu’s UFW (Uncomplicated Firewall). It often defaults to blocking port 80, meaning traffic passes the outer gate but dies at the inner door.

Issue 2: Broken Icons & The CORS Mismatch

Once the timeout is fixed, you might notice your beautiful icons have turned into empty squares or garbled characters. Opening the F12 Console reveals multiple Access-Control-Allow-Origin (CORS) errors.

The Underlying Logic:
This is a classic CORS (Cross-Origin Resource Sharing) restriction. Browsers treat www.yourdomain.com and yourdomain.com as two entirely different entities.

  • Page Loaded from: https://www.yourdomain.com
  • Font Resource Requested from: https://yourdomain.com (Missing the ‘www’)

Because the domains don’t match exactly, the browser blocks the font files for security, breaking your UI.

The Solution: Domain Unification

Conclusion: The Power of Standardization

When deploying on cloud platforms like AWS, every node in the network chain—Security Groups, System Firewalls, Redirect Rules, and App Configs—must be logically aligned.

  • Is the network reachable? Check both firewall layers (AWS Security Group + UFW).
  • Are the resources loading? Ensure your domain is unified to eliminate CORS issues.

By forcing traffic to a single Naked Domain (https://yourdomain.com/), you not only fix visual bugs but also prevent SEO “link juice” dilution.

Now, whether it’s the first visit or a deep-link navigation, your website will provide a seamless, secure, and instant experience.
