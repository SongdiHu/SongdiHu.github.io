Hexo Troubleshooting Guide: GitHub SSH Setup and Image Path Fixes

Created2026-02-24|Web Development
|Post Views:

When setting up and deploying a Hexo blog, it’s easy to run into frustrating errors due to environment configurations and dependency details. This post breaks down the two most critical pitfalls I encountered during my setup: GitHub Authentication Failure and Image 404 Errors, along with their ultimate solutions.

Topic 1: GitHub Deployment Credential Error (SSH Key Setup)

1. The Symptom

When trying to deploy the blog to GitHub Pages using hexo d, the terminal throws the following error and aborts the deployment:
remote: Invalid username or token. Password authentication is not supported for Git operations.
fatal: Authentication failed for 'https://github.com/...'

2. Root Cause Analysis

GitHub officially disabled password authentication for HTTPS connections a while ago. If your Hexo _config.yml is configured with an HTTPS repository link, Git will try to prompt for a password, resulting in an authentication failure.

3. The Solution: Switch to SSH Authentication

You need to generate an SSH key on your local machine and add it to your personal GitHub account.

Step 2: Add the Public Key to GitHub

  1. Copy the entire contents of your public key: cat ~/.ssh/id_rsa.pub
  2. Log in to GitHub, click your profile picture in the top right -> Settings -> SSH and GPG keys -> New SSH key.
  3. Give it a descriptive title (e.g., “MacBook Pro M1”), paste the copied key into the box, and save.

    Warning: You must add this to your Personal Account Settings, NOT to the “Deploy keys” of a specific repository. Otherwise, you will get a Permission denied error.

Topic 2: Image 404s and Path Stacking

1. The Symptom

After successfully deploying the blog, the homepage looks fine, but when you click into an article or check the “Recent Posts” sidebar thumbnails, the images are broken (404).
If you open the browser console (F12), you’ll notice the image request URLs look incredibly weird, stacking the paths of two different posts together:
https://yoursite.com/2020/08/10/Post-A/2026/02/24/Post-B/cover.png

2. Root Cause Analysis

This is a classic relative path resolution error in frontend development.
When we are on the page for Post A and the browser tries to load the cover image for Post B (cover.png): because the referenced path doesn’t start with a slash / (meaning it’s not an absolute path), the browser simply appends cover.png to the end of Post A’s current URL, causing it to look in the wrong place entirely.

3. The Solution: Auto-Prepend Absolute Paths
